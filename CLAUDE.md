## Architecture

### Build Pipeline

`site.hs` (entry point) defines all Hakyll rules. It imports modules from `src/`:

| Module | Purpose |
|--------|---------|
| `src/Config.hs` | Site-wide constants: `templateDir`, `hakyllConfig`, `textaliveToken` |
| `src/Compilers.hs` | `sassCompiler` (npx sass) and `tsCompiler` (npx esbuild) |
| `src/ChartCompiler.hs` | `chartCompiler` ΓÇö compiles `.mimi` chart files into `Note[]` JSON; an `auto` (or empty) `degrees` field compiles with no `directionPinned`, a numeric value emits `"directionPinned": true`; a `break` line sets `"newCombo": true` on the next note (flow phrase boundary); lyric trailing tokens parse bare/`char=<text>` overrides as `"lyricChar"`, `span=N` as `"lyricSpan"`, `src=<ms>` as `"lyricSrcTime"`, and `endchar` as `"includeEndChar": true`; an `end, time` line emits an inert lyric-end marker |
| `src/StoryCompiler.hs` | `storyCompiler` ΓÇö compiles `.story` storyboard files into JSON arrays of highlight/move/exclude/reactive/lyric entries (`x, t1, t2` ΓåÆ `{type:"exclude"}`, keeps a time range of TextAlive chars out of lyric-note matching; `reactive: <modes>` ΓåÆ `{type:"reactive"}`; `m`/`l` accept optional trailing `key=value` style tokens emitted as a `"style"` object) |

`site.hs` also generates `sitemap.xml`: its `sitemapLocs` helper emits one absolute `<loc>` per (song, available difficulty) as `<origin><sitePath>/<songId>/?d=<difficulty>` (e.g. `https://twigums.github.io/mimi/kotaete/?d=hard`), plus the site root. Origin comes from `SITE_ORIGIN` (default `http://localhost`); info/tutorial are embedded into the home page, not standalone pages, so they are excluded.

A cut is scored as **one coherent stroke**: besides direction/contact/travel, a `CUT_STRAIGHT_*` **path-straightness** cap (net displacement ├╖ path length of the chosen slice, via a cumulative arc-length prefix sum) holds any slice that passes the note while reversing below tier 3, so contact and direction can't be borrowed from different motions in the window (issue #74 ΓÇö a backward/flailing swipe now fails instead of cherry-picking an aligned endpoint pair). Straightness applies to cut only (flow ribbons bend; lyrics ignore heading) and is reported in the `gesture` issue slot; `candidateSortKey` ranks gesture substance (travel, straightness) ahead of direction so a real reversed sweep out-ranks a degenerate zero-travel candidate parked at the note, making the binding issue read `direction` not `gesture`. `canStillImprove` holds a pending note until a better timing tier becomes impossible; to keep non-perfect feedback from lagging behind an **early** cut (issue #53), `gestureSettled` finalizes a cut hit early once the pointer has left the contact zone (`> CUT_CONTACT_TIER1`), gated so the earliest commit (`cutEarliestCommitMs`) is `max(note.time ΓêÆ TIER1_MS, prevNoteTime)` ΓÇö never before the note's own GOOD window opens, and never during the previous note's territory (a sweep toward an adjacent note can't claim this note early). `engine.ts` passes `notes[iΓêÆ1].time` as `prevNoteTime`. Flow anchors are judged as a traced ribbon by a single **shape** metric (no separate flow direction cap): `flowShapeCap` reduces both the chosen gesture and the ribbon's local shape (`note.flowShape`, set by `engine.ts`) to a `FLOW_SHAPE_BINS`-length arc-length heading sequence via `resampleHeadings`, and caps on the RMS per-bin heading error (`FLOW_CONT` 60/75/100┬░ ΓÇö so a ~90┬░-off sweep is GOOD not GREAT and >100┬░ misses) ΓÇö position-invariant, so it reads how the gesture *follows the curve's bend*, not distance. It's reported in the **`gesture`** issue slot ΓÇö the four `IssueReason` buckets are `timing`/`contact`/`direction`/`gesture`, where `gesture` is the binding-constraint slot for a cut's travel/slash, a flow's traced shape, and a lyric's hold completeness (there is no separate `travel`/`flow`/`continuity`/`hold` issue); `direction` applies to cut only (lyric and flow have none). A lone flow anchor has no `flowShape` and is judged on motion only; the previous anchor's grade is irrelevant (no cascade). Flow's perfect/great timing windows are looser than cut via `timingTiers` (`FLOW_TIER3/2_MS` 70/120 ms vs 40/80); Tier 1 stays at the shared `TIER1_MS` so the engine's eligibility/expiry/draw windows are unaffected. **Lyrics are holds**: `judgeGesture` dispatches `kind === "lyric"` to `judgeHold`, which keeps the same `pending`/`judged` protocol but scores a held position rather than a stroke ΓÇö `timing` = enter offset (early presence counts as on-time, only late entry is penalized), `contact` = closest distance to center (cut thresholds), `gesture` = the held fraction of the required duration (`holdMs ΓêÆ LYRIC_RELEASE_GRACE`) against `LYRIC_HOLD_TIER3/2/1`, where "held" is the longest contiguous span inside `LYRIC_HOLD_RADIUS`. It finalizes on release (pointer leaves the circle), on a full hold, on a lapsed-timing miss, or at `holdEnd`

### Chart Format (`.mimi`)

Each difficulty is a separate file: `src/songs/<name>/<difficulty>.mimi` (e.g. `easy.mimi`, `expert.mimi`). `site.hs` scans for these files to build the song manifest; `ChartCompiler.hs` compiles each to `songs/<name>/<difficulty>.json`.

```
time_unit: ms
difficulty: 12
beats_per_measure: 4

# kind, time_ms, degrees, x, y[, lyric_option...]
cut,  2388, -30.6, 396.9,  92.2
flow, 3080,  auto, 381.3, 425.0
flow, 3300,    90, 360.0, 480.0
break
flow, 4000,  auto, 300.0, 200.0
lyric, 5000, auto, 300.0, 250.0
lyric, 5500, auto, 400.0, 300.0, char=πüï, endchar
```

- `bpm`: song tempo; read by `site.hs` from the first available difficulty file and included as a numeric `bpm` field in the songs manifest JSON
- `time_unit`: always `ms`
- `difficulty`: integer level shown on the difficulty selection button
- `beats_per_measure`: optional, informational only
- `kind`: `c`/`cut` (red directional slash), `f`/`flow` (blue connected phrase anchor), or `l`/`lyric` (white **hold** circle, text auto-filled from every TextAlive char in the hold window; held from the note time until the next event strictly after it ΓÇö the next note or an `end` marker ΓÇö a lyric may not be the last event ΓÇö see Lyric Judgement in `/wiki/gameplay.md`)
- `lyric_option` (lyric notes only, optional): trailing tokens after `x, y`; bare text or `char=<text>` overrides displayed text and compiles to `"lyricChar"`, `span=N` compiles to `"lyricSpan"`, `src=<ms>` compiles to `"lyricSrcTime"`, and `endchar` compiles to `"includeEndChar": true` so the auto hold-window text includes the closing syllable. Options can be combined (`lyric, t, auto, x, y, char=πüï, span=2, src=12345, endchar`)
- `time_ms`: milliseconds from song start when the note should be hit
- `degrees`: direction in screen coordinates (0 = right, 90 = down, -90 = up); converted to runtime radians on compile. Cut notes always use it; lyric notes ignore it. For a flow anchor it is optional ΓÇö `auto` (or an empty field, e.g. `s, t, auto, x, y`) derives direction from the ribbon tangent (compiler sets no `directionPinned`), while a numeric value **pins** that anchor's tangent (compiler emits `"directionPinned": true`)
- `x`, `y`: logical game coordinates (800 ├ù 600 space)
- `break`: a standalone line (no fields) that ends the current flow phrase ΓÇö the next flow anchor starts a new phrase. Flow phrases are explicit (a `break` or a non-flow note bounds them), not auto-detected by timing
- `end`: an `end, time` line (no other fields) ΓÇö an inert lyric-end marker that bounds a preceding lyric's hold at `time` without placing a playable note; the engine uses its time then discards it
- Full-word kinds (`cut`/`flow`/`lyric`) are preferred in authored charts; `c`/`f`/`l` are accepted shorthands
- Blank lines and `#` comment lines are ignored

### Story Format (`.story`)

An optional per-difficulty `src/songs/<name>/<difficulty>.story` file compiled by `StoryCompiler.hs` to `songs/<name>/<difficulty>.story.json`. Loaded at runtime by `controller.ts` alongside the matching chart and applied via `storyboard.setStoryData()`.

```
# kind, argsΓÇª
h, 62500, 63200
m, 63000, 550, 300
```

- `h, time1, time2` ΓÇö highlight: while song position is in `[time1, time2]`, any storyboard character whose `startTime` is also in that range gets the technicolor `.approach` style
- `m, time, x, y` ΓÇö move: within the current phrase, characters with `startTime >= time` break into a separate vertical segment absolutely positioned at logical `(x, y)` (800 ├ù 600 space); multiple `m` entries divide the phrase into multiple segments
- `x, time1, time2` ΓÇö exclude: any TextAlive character whose `startTime` falls within `[time1, time2]` is kept out of lyric-note matching (`lyricMatch.ts` pre-consumes it), so backing/unwanted lyrics are never claimed by a note
- `l, from, to, x, y, text[, char_time1, char_time2, ...]` ΓÇö manual lyric: a self-contained lyric segment, completely independent of TextAlive; appears at `from` ms, fades out at `to` ms, absolutely positioned at logical `(x, y)`; `text` is the lyric string (must not contain commas); each optional `char_time` is the ms when the corresponding character becomes `.active` (prior character transitions to `.sung`); the last character stays `.active` until `to`
- `reactive: <modesΓÇª>` ΓÇö optional header line (space-separated `amplitude` / `mood` / `chorus`) enabling live song-map effects: `amplitude` scales active chars by `getVocalAmplitude/getMaxVocalAmplitude`, `mood` tints the storyboard from `getValenceArousal`, `chorus` brightens chars inside `getChoruses()` ranges. `controller.ts` computes a `ReactiveFrame` per tick (only for enabled modes / when any segment uses `pulse`) and passes it to `storyboard.update`
- **Per-segment style directives** (optional trailing `key=value` tokens on `m`/`l`; all default-off): `color=#rrggbb`, `font=<display|handwriting|family>` (handwriting = Yomogi, loaded in `imports.html`; `--font-handwriting`), `scale=<mult>` (em font-size), `in=<grow|fade>` / `out=<rise|fade>` (one-shot entrance/exit), `motion=<sway|drift|rotate>` (continuous), `pulse=beat` (per-frame scale from `findBeat().progress`), and (on `l`) the `autotime` flag (derive per-char activation from TextAlive `char.startTime` instead of a manual `char_time` list). On `l`, numeric trailing tokens are still `char_time`s; `k=v`/flags are style. The storyboard nests three transform layers (`.storyboard-segment`/`-line` position ΓåÆ `.sb-fx` motion ΓåÆ `.sb-enter` entrance ΓåÆ char pulse) so the effects never collide
